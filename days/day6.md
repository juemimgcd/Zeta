# Day 6：Compaction：缩短视图，保留事实

[总览](summary.md) · [配套基础代码](support.md)

## 核心问题

什么时候历史应该变短？删哪里才不会拆散工具协议？摘要错了又怎么办？这三件事由你决定，生成摘要的单次模型调用直接复用。

## 已提供与本日范围

- 计划新增 `src/zeta/compaction.py`，供 ContextBuilder 在安全边界调用。
- 可选阅读：Pi core/compaction/compaction.ts，重点看保留边界与覆盖来源；不要逐行翻译。
- 先做确定性的旧历史裁减，再加模型摘要；摘要请求不带行动工具定义，也不运行工具 Loop。

## 你手写的入口

```python
def choose_compaction_range(entries, keep_recent):
    """只选旧的完整交互，保留当前问题与最近交互。"""
    ...


async def compact(entries, previous_summary, summarize_once):
    """生成带覆盖范围的摘要；失败不覆盖旧的有效视图。"""
    ...
```

只在无 pending tool call 的边界压缩。先定义“完整交互”：从用户输入到最终 assistant 回答，内部全部 call/result 成对；若一个交互本身超大，交给工具输出受限视图或明确报错，不硬切。
摘要包含目标、约束、事实、决策、改动、错误和下一步；记录 covered entry IDs、版本和生成时间，保留原始记录。上次摘要与新覆盖内容合并时，不遗漏旧覆盖范围，也不重复计入原文。
设可配置触发阈值和更低的压缩目标，避免每一轮都压缩。overflow 最多压缩重试一次；仍失败就停止。

## 怎样算完成

用实际累积的多轮历史查看压缩前后：最近完整交互保留、旧信息可追溯、原 Session 未删除，输入估算下降。摘要不得把未执行的工具写成已经完成。
如果历史尚短，不为展示效果生成假记录；先完成边界审阅，标明真实长会话待验证。
